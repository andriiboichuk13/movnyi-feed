# Мовний фід: бекенд і наповнення бази

## Що тут є

| Файл | Що робить |
|---|---|
| `server.py` | Сервер для розширення і сайту: `/alternatives`, `/classify`, `/wish`, `/events`, `/actions` |
| `ingest.py` | Наповнює базу: таблиця каналів → YouTube API → вектори → Supabase |
| `search.py` | Перевірка: шукає в базі українські відео, найближчі до будь-якого тексту |
| `lang.py` | Визначення мови відео (та сама логіка, що в розширенні, плюс `defaultAudioLanguage`) |
| `youtube.py` | Робота з YouTube Data API |
| `config.py` | Модель, пороги схожості, ліміти й інші налаштування |
| `uk_dubs.txt` | Ручний список англомовних відео з українським дубляжем |
| `logs/alternatives_v2.csv` | Лог кожної відповіді зі схожістю, для підбору порогів |
| `.env` | Ваші секрети. Ніколи не публікуйте і не кладіть у git |

## Перший запуск (Windows, PowerShell)

У папці `backend`:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

Перша команда створює окреме середовище Python для проєкту, друга встановлює бібліотеки (кілька хвилин, PyTorch важить кілька сотень МБ).

У `.env` мають бути три рядки (приклад у `.env.example`):

```
YOUTUBE_API_KEY=...
DATABASE_URL=...
CHANNELS_SHEET=посилання на Google-таблицю
```

Наповнення бази:

```powershell
.venv\Scripts\python ingest.py
```

Перевірка, що пошук працює:

```powershell
.venv\Scripts\python search.py "НОУТБУК ПО ЦЕНЕ АВТО"
```

Перший запуск завантажить модель (близько 0,5 ГБ), далі вона береться з кешу.

## Сервер

```powershell
.venv\Scripts\python -m uvicorn server:app --port 8000
```

Перевірка в браузері: `http://localhost:8000/health` показує кількість відео в базі і скільки пошуків YouTube витрачено сьогодні. На `http://localhost:8000/docs` можна вручну викликати будь-який ендпоінт, наприклад `/alternatives` з id будь-якого відео.

Щоб розширення ходило на сервер: у `extension/src/config.js` поставте `API_BASE: "http://localhost:8000"` і `USE_MOCK: false`, оновіть розширення в `chrome://extensions`.

### Як сервер підбирає альтернативи (драбина з ТЗ)

1. Схожість з відео в базі ≥ 0.86 → рівень 1, «та сама тема».
2. Інакше один пошук YouTube українською (`search.list`, 100 одиниць квоти) → рівень 2.
3. Інакше відео з бази зі схожістю 0.84–0.86 → рівень 3, «близька тема».
4. Інакше пошук YouTube англійською → рівень 4.
5. Нічого не знайшли → рівень 5, лише кнопка «Хочу українське».

Українське вихідне відео отримує рівень 0 і порожній список: панель не показується.

Не більше двох відео з одного каналу. Збіг чисел і латинських назв (iPhone, 16, RTX) трохи підсилює кандидата. Пошуків YouTube не більше 80 на день, потім драбина пропускає рівні 2 і 4. Готова відповідь кешується на 24 години, тож повторний перегляд того самого відео квоти не витрачає. Щоб отримати свіжу відповідь, додайте до запиту `&fresh=true`.

Як рахується схожість: окремо назва з назвою і окремо «назва + теги + опис», порівну (`TITLE_WEIGHT`). З опису перед цим прибираються посилання, промокоди, соцмережі й «підписуйтесь», а назви глав з таймкодами лишаються. Відео з того самого каналу, що й вихідне, не пропонуються.

Для підбору порогів: `http://localhost:8000/alternatives?videoId=…&debug=true`. Відповідь свіжа, без кешу й без пошуку YouTube (квота не витрачається), і містить 10 найкращих кандидатів з бази з усіма цифрами схожості, а також текст, за яким шукали.

Коли змінюєте алгоритм, збільшуйте `ALGO_VERSION` у `config.py`: при старті сервер сам очистить старі готові відповіді.

Пороги, ліміти й тривалість кешу лежать у `config.py`. Кожна відповідь записується в `logs/alternatives_v2.csv` (відкривається в Excel чи Google Sheets) разом зі схожістю найкращого відео з бази: по цьому файлу підбираємо пороги.

### Швидкість

Кожна нова відповідь пише в лог сервера рядок на кшталт `[alt] VIDEO_ID default рівень 1 total=850ms source=320ms embed=90ms index=210ms save=40ms`: скільки зайняв кожен етап. Відповідь з кешу позначається «з кешу». На Railway ці рядки видно в Deployments → View Logs.

`TORCH_THREADS` (змінна середовища, за замовчуванням 2) обмежує кількість потоків PyTorch. Без цього в контейнері модель може працювати в рази повільніше.

## Таблиця каналів

Скрипт читає Google-таблицю напряму. У таблиці: «Поділитися» → «Загальний доступ» → «Усі, хто має посилання» → «Читач». Посилання на таблицю вставте в `CHANNELS_SHEET` як є, скрипт сам перетворить його на CSV. Якщо в таблиці кілька аркушів, беріть посилання, відкривши потрібний аркуш (у ньому є `gid=`).

Замість посилання можна вказати шлях до CSV-файлу: `CHANNELS_SHEET=channels.csv`.

Колонки: `channel_url, name, topic, kids, status, uk_since, checked_by, source, notes`. Скрипт бере лише `status = approved`. Дату в `uk_since` пишіть як `2024-03-01`.

Посилання на канал має бути у вигляді `youtube.com/@назва` або `youtube.com/channel/UC…`. Старі посилання `youtube.com/c/назва` API не розуміє: відкрийте канал і скопіюйте нову адресу з рядка браузера.

## Що відсіюється

Shorts і всі відео до 3 хвилин (для каналів з `kids = yes` лише до 1 хвилини, бо дитячі пісні й мультики часто коротші за 3 хвилини), трансляції, відео недоступні в Україні, відео до дати `uk_since` і відео іншою мовою. Мова визначається за `defaultAudioLanguage`, а якщо його немає, то за назвою й описом. Якщо автор лишив у `defaultAudioLanguage` «ru» за замовчуванням, а текст упевнено український, скрипт вірить тексту. Відео, мову яких не вдалося визначити, лишаються: канал же перевірила людина.

## Як часто запускати

Повторний запуск безпечний: існуючі відео оновлюються, нові додаються. Відео, не оновлені 30 днів, видаляються (вимога правил YouTube API), а канали, яких більше немає серед `approved`, прибираються з бази.

Скрипт бере до 200 останніх відео з каналу (`MAX_VIDEOS_PER_CHANNEL` у `config.py`). Квота: близько 9 одиниць на канал, тобто 150 каналів коштують приблизно 1 350 з 10 000 одиниць на день.

Вектори рахуються лише для нових або змінених відео: у кожного відео є відбиток тексту, і якщо назва, теги й опис не змінились, скрипт лише оновлює дату. Тому перший запуск на великому каталозі довгий (кілька десятків хвилин), а наступні швидкі.
